# 세대 인증 설치·운영

> 이 문서는 현재 탭에서 **운영자**로 인증된 경우에만 가이드 UI에 표시됩니다. 정적 GitHub Pages의 원본 파일과 자산 자체를 비공개로 만드는 보안 장치는 아닙니다.

## 인증명단 구조

`인증명단` 탭은 다음 네 열만 사용합니다.

| 동 | 타입 | 닉네임 | 상태 |
| --- | --- | --- | --- |
| 105 | 55A | 피치 | 인증됨 |

- 타입은 `51A`, `55A`, `55B`, `59A` 중 하나입니다.
- 상태는 `요청`, `인증됨`, `운영자` 중 하나입니다.
- 사용자가 선택한 층과 호수는 시트나 인증 세션에 저장하지 않습니다. 프런트엔드가 세대 카탈로그에서 타입과 층을 계산하고, 인증 요청에는 동·타입·닉네임만 전송합니다.

## 상태의 의미

| 상태 | 쇼케이스 | 운영자 메뉴 |
| --- | --- | --- |
| 요청 | 진입 불가 | 진입 불가 |
| 인증됨 | 진입 가능 | 진입 불가 |
| 운영자 | 진입 가능 | 검수맵·건축물·인테리어·전체 동호 현황 사용 가능 |

사용자가 **인증 요청**을 누르면 일치하는 행이 없을 때 `요청` 상태로 새 행이 추가됩니다. 이미 `인증됨` 또는 `운영자`인 행은 요청으로 낮아지지 않습니다. 운영자는 Sheet에서 상태를 검토해 직접 변경합니다.

## 설치와 재배포

1. 저장소의 `backend/apps-script/Code.gs` 전체를 Sheet의 Apps Script 편집기에 붙여 넣습니다.
2. `setupVerificationSheet()`를 한 번 실행해 A1:D1 헤더와 상태 드롭다운을 준비합니다.
3. `배포 관리 → 수정 → 새 버전`으로 웹앱을 다시 배포합니다.
4. 실행 사용자는 `나`, 액세스 권한은 `모든 사용자`로 유지합니다.
5. 공개 사이트는 `public/config/household-verification.v1.json`의 `/exec` 주소를 사용합니다.

기존 `동 | 호수 | 닉네임` 데이터가 있으면 먼저 별도 시트로 백업하고, B열을 타입으로 바꾸고 D열에 상태를 넣은 뒤 설치 함수를 다시 실행합니다. 설치 함수는 기존 데이터를 자동으로 덮어쓰지 않습니다.

## 운영 절차

1. Sheet에서 `요청` 행의 동·타입·닉네임을 확인합니다.
2. 일반 사용자는 상태를 `인증됨`, 관리 담당자는 `운영자`로 변경합니다.
3. 사용자에게 같은 탭에서 **인증 확인**을 다시 누르도록 안내합니다.
4. 권한을 회수하려면 상태를 `요청`으로 바꾸거나 행을 삭제합니다. 이미 열린 탭의 세션은 탭 종료 또는 **세대 다시 선택** 전까지 남을 수 있습니다.

Apps Script 주소는 공개 주소이며 비밀키가 아닙니다. Spreadsheet ID와 실제 명단은 저장소, Markdown, 배포 산출물에 넣지 마세요. 공개 요청 API에는 자동 명단 조회나 행 열거 기능이 없습니다.
