# Bunfirvil Google Sheet 인증 설치

공개 GitHub Pages가 선택 세대에서 계산한 `동·타입`과 사용자가 입력한 `닉네임`을 이 Apps Script에 보냅니다. 층과 호수는 보내지 않습니다. 비공개 Sheet는 인증 상태만 반환하며 명단이나 일치 행은 반환하지 않습니다.

## 1. Google Sheet 준비

1. 인증용 Google Sheet에서 `확장 프로그램 → Apps Script`를 엽니다.
2. 기본 코드를 지우고 [`Code.gs`](Code.gs) 전체를 붙여 넣어 저장합니다.
3. 함수 목록에서 `setupVerificationSheet`를 선택해 한 번 실행하고 최초 권한을 승인합니다.

`인증명단` 탭은 다음 네 열을 사용합니다.

| A | B | C | D |
| --- | --- | --- | --- |
| 동 | 타입 | 닉네임 | 상태 |
| 105 | 55A | 피치 | 인증됨 |

- 타입: `51A`, `55A`, `55B`, `59A`
- 상태: `요청`, `인증됨`, `운영자`
- 닉네임은 앞뒤 공백과 Unicode 표현만 정리하며 내부 공백과 영문 대소문자를 구분합니다.

기존 `동 | 호수 | 닉네임` 시트에 데이터가 있으면 설치 함수가 덮어쓰지 않고 중단합니다. 먼저 백업한 뒤 B열을 타입으로 바꾸고 D열에 상태를 입력하세요. 데이터가 없는 구형 헤더는 새 네 열로 자동 전환됩니다.

## 2. 상태와 사용자 흐름

| 상태 | 인증 확인 | 사용할 수 있는 화면 |
| --- | --- | --- |
| 요청 | 실패·확인 대기 | 없음 |
| 인증됨 | 성공 | 렌더 쇼케이스 |
| 운영자 | 성공 | 렌더 쇼케이스와 검수맵·건축물·인테리어·전체 동호 현황 |

사용자가 **인증 요청**을 누르면 일치 행이 없을 때 `요청` 행이 추가됩니다. 같은 조합이 이미 `인증됨` 또는 `운영자`이면 상태를 낮추지 않습니다. 운영자는 Sheet에서 검토 후 상태를 직접 바꿉니다.

## 3. 웹앱 배포

1. Apps Script의 `배포 → 새 배포 → 웹 앱`을 선택합니다.
2. 실행 사용자는 `나`, 액세스 사용자는 `모든 사용자`로 지정합니다.
3. 발급된 `https://script.google.com/macros/s/.../exec` 주소를 복사합니다.
4. 코드를 수정할 때마다 `배포 관리 → 수정 → 새 버전`으로 다시 배포합니다. `/dev` 주소는 공개 설정에 사용하지 않습니다.

## 4. Bunfirvil 연결

`public/config/household-verification.v1.json`에는 `/exec` 주소만 넣습니다. Spreadsheet ID와 실제 명단은 저장소나 설정 파일에 넣지 않습니다.

```json
{
  "schemaVersion": 1,
  "enabled": true,
  "provider": "google-apps-script",
  "endpoint": "https://script.google.com/macros/s/배포_ID/exec",
  "timeoutMs": 8000
}
```

## 5. 운영 확인

1. 임시 `동 | 타입 | 닉네임 | 요청` 행으로 인증 확인이 대기 상태인지 봅니다.
2. 상태를 `인증됨`으로 바꿔 쇼케이스 진입을 확인합니다.
3. 상태를 `운영자`로 바꾼 새 탭에서 네 운영자 메뉴가 나타나는지 확인합니다.
4. 확인 후 임시 행을 삭제합니다.

운영자 메뉴 차단은 정적 사이트의 UI 권한입니다. GitHub Pages에 배포된 HTML·JavaScript·자산 자체를 비공개로 만들지는 못합니다. 강한 접근통제가 필요하면 인증 가능한 서버나 비공개 호스팅 계층이 별도로 필요합니다.
